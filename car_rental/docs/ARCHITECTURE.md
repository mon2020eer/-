# 🏛️ معمارية منظومة إدارة مكتب إيجار السيارات

وثيقة تقنية تشرح البنية ومخطط قاعدة البيانات و**أسباب** القرارات الجوهرية،
لا وصفها فقط.

---

## ١. نظرة عامّة

```
┌──────────────────────────────────────────────────────────┐
│  ui/          واجهة PyQt6 عربية RTL                      │
│               نوافذ · صفحات · حوارات · عناصر مشتركة        │
├──────────────────────────────────────────────────────────┤
│  services/    منطق العمل المركّب                          │
│               التسعير · العقود · التقارير · PDF · النسخ    │
├──────────────────────────────────────────────────────────┤
│  repositories/  قراءة وكتابة الكيانات                     │
│               مستخدمون · عملاء · سيارات · عقود · دفعات      │
├──────────────────────────────────────────────────────────┤
│  core/        الأساس                                      │
│               db · security · session · money · audit     │
├──────────────────────────────────────────────────────────┤
│  SQLite (WAL)  ملف واحد في %APPDATA%                     │
└──────────────────────────────────────────────────────────┘
```

**قاعدة الاتجاه:** الطبقة الأعلى تستدعي الأدنى فقط. `core` لا يعرف شيئاً عن
`ui`، و`services` لا تستورد أي عنصر واجهة (عدا `contract_pdf` الذي يستخدم
محرّك نصوص Qt للطباعة). النتيجة العملية: **١١٤ اختباراً يعمل معظمها بلا واجهة
رسومية إطلاقاً**.

## ٢. القرارات التقنية وأسبابها

| القرار | البديل المرفوض | السبب |
|---|---|---|
| **PyQt6** | CustomTkinter | دعم RTL أصيل على مستوى التطبيق، وتشكيل عربي صحيح، وطباعة PDF مدمجة |
| **PDF عبر QTextDocument** | ReportLab | ReportLab لا يصل الحروف العربية ولا يشكّلها، فيحتاج `arabic-reshaper` + `python-bidi` + خطوطاً مُضمَّنة، والنتيجة هشّة |
| **PBKDF2-HMAC-SHA256** | bcrypt | مدمجة في بايثون، بلا تبعية ثنائية تُفشل حزم PyInstaller على ويندوز |
| **مبالغ بأعداد صحيحة** | `float` | `0.1 + 0.2 ≠ 0.3`؛ تراكم الخطأ في عقود كثيرة يُنتج فروقاً مالية حقيقية |
| **مشغّل منع التداخل** | فهرس فريد على العقود المفتوحة | الفهرس يمنع الحجز المسبق الذي يحتاجه مكتب محدود السيارات؛ والمشغّل يمنع الخطأ الحقيقي وحده: تداخل الفترات |
| **سعر ساعة افتراضي بالتقريب لأعلى** | التقريب لأسفل | `daily/24` مقرَّباً لأسفل يجعل 24 ساعة أرخص من يوم كامل، فيصير الاحتساب بالساعة ثغرةً لا تسوية |
| **حالة الدفع مُشتقّة** | عمود مخزَّن | العمود المخزَّن يتناقض مع الدفعات عند أي خطأ؛ الاشتقاق يجعل التناقض مستحيلاً |
| **لقطة السعر في العقد** | القراءة من السيارة | رفع التعرفة اليوم كان سيغيّر قيمة عقود العام الماضي |
| **`onedir` في PyInstaller** | `onefile` | إقلاع أسرع وإنذارات مضادات فيروسات أقل |
| **نطاق `drive.file`** | `drive` الكامل | أقلّ امتياز يؤدّي الغرض: التطبيق يرى ملفاته هو فقط |
| **بيانات في `%APPDATA%`** | بجوار البرنامج | `Program Files` غير قابل للكتابة، والتحديث لا يجب أن يمسّ البيانات |

## ٣. مخطط قاعدة البيانات

### العلاقات

```
users ──┬─< contracts (created_by, closed_by)
        ├─< payments (recorded_by)
        └─< audit_log

customers ──┬─< contracts
            └─< customer_attachments

vehicles ──┬─< contracts
           ├─< maintenance_records
           └─< violations

contracts ──┬─< payments
            └─< violations

currencies ──< vehicles, contracts, maintenance_records, violations
```

### الجداول

| الجدول | الدور |
|---|---|
| `users` | الحسابات والصلاحيات وحالة القفل |
| `customers` | المستأجرون |
| `customer_attachments` | وثائق العملاء (مسارات نسخ محلية) |
| `vehicles` | الأسطول والتعرفة (يومية وأسبوعية وبالساعة) والحالة |
| `contracts` | العقود مع لقطات السعر وسعر الصرف وسعر الساعة وأوقات الاستلام والتسليم |
| `payments` | كل دفعة على حدة (عربون/دفعة/مبلغ مُعاد) |
| `maintenance_records` | سجلّات الصيانة وتكاليفها |
| `violations` | المخالفات المرورية |
| `currencies` | العملات وأسعار صرفها |
| `backup_logs` | كل محاولة نسخ أو استعادة ونتيجتها |
| `audit_log` | من فعل ماذا ومتى |
| `app_settings` | إعدادات مفتاح/قيمة |

### القيد الأهم في المنظومة كلّها

```sql
CREATE TRIGGER trg_contracts_no_overlap_insert
BEFORE INSERT ON contracts FOR EACH ROW
WHEN NEW.status <> 'cancelled' AND EXISTS (
    SELECT 1 FROM contracts c
     WHERE c.vehicle_id = NEW.vehicle_id
       AND c.status <> 'cancelled'
       AND c.start_date < MAX(COALESCE(NEW.actual_end_date, NEW.expected_end_date),
                              date(NEW.start_date, '+1 day'))
       AND NEW.start_date < MAX(COALESCE(c.actual_end_date, c.expected_end_date),
                                date(c.start_date, '+1 day'))
)
BEGIN
    SELECT RAISE(ABORT, 'contract_period_overlap');
END;
```

**لماذا مشغّل لا فهرس فريد؟** الإصدار الأول استعمل فهرساً فريداً جزئياً يمنع
وجود عقدين مفتوحين لسيارة واحدة. وقد تبيّن في التشغيل أن هذا القيد **يعطّل
العمل**: المكتب محدود عدد السيارات، ويحتاج أن يحجز السيارة لعميل قادم قبل أن
يعيدها العميل الحالي. الخطأ الحقيقي ليس تعدّد العقود، بل **تداخل فتراتها**.

و«عدم التداخل» شرط بين صفّين لا يمكن التعبير عنه بفهرس، بينما يستطيع مشغّل
SQLite رفض الإدراج المتداخل — فتبقى الضمانة داخل المحرّك نفسه، لا يتخطّاها خطأ
برمجي ولا خيطان متزامنان ولا إدراج بـ SQL خام.

**الفترة نصف مفتوحة [البداية، النهاية)**: يوم التسليم يصلح بدايةً لعقد تالٍ،
لأن من يُعيد السيارة يوم ١٧ تُسلَّم لعميل آخر في اليوم نفسه — وهو ما يفعله
المكتب فعلاً. ولولا ذلك لتعذّر تجديد العقد أو تسليم السيارة لعميل تالٍ.

اختبارا `test_database_trigger_blocks_overlap_even_bypassing_service` و
`test_trigger_allows_non_overlapping_raw_insert` يثبتان الطرفين بتجاوز طبقة
الخدمة عمداً.

### حالة السيارة مُشتقّة لا مُدخَلة

مع تعدّد العقود على السيارة الواحدة، لم تعد الحالة تُضبط يدوياً عند كل عملية،
بل تُشتقّ في `vehicles_repo.sync_status()`:

| الواقع | الحالة |
|---|---|
| صيانة مفتوحة | `maintenance` |
| عقد مفتوح يشمل تاريخ اليوم | `rented` |
| غير ذلك — ولو كانت محجوزة لتاريخ قادم | `available` |

ولأن **مرور الوقت وحده يغيّر الحقيقة** (حجز الغد يصير إيجار اليوم، وعقد انتهى
أمس يترك سيارته متاحة، وقد يقع ذلك والتطبيق مغلق)، تُزامَن حالات الأسطول كلّها
عند كل إقلاع عبر `sync_all_statuses()`.

### العروض (Views)

- **`v_contract_balance`**: المدفوع والمتبقّي وحالة الدفع لكل عقد، محسوبة من
  جدول الدفعات (وتطرح المبالغ المُعادة).
- **`v_contracts_full`**: العقود موسّعة بأسماء العميل والسيارة وحالة الدفع —
  استعلام واحد يغذّي جدول العقود والبحث والتقارير.

## ٤. حماية المال

### الوحدة الصغرى

كل مبلغ `INTEGER` بالوحدة الصغرى: `150.00` يُخزَّن `15000`. التحويل يقع في
`core/money.py` وحده، والعرض فقط هو ما يرى الفاصلة العشرية.

### أسعار الصرف

تُخزَّن مضروبة في مليون (`5.25` ← `5250000`) للسبب نفسه. كل عقد يحمل
`rate_to_base` وقت إنشائه، فتُجمَّع التقارير بذلك السعر لا بسعر اليوم:

```sql
SUM(total_amount * rate_to_base / 1000000)
```

يثبت ذلك اختبار `test_multi_currency_reporting_uses_contract_rate`: يغيّر سعر
الصرف بعد العقد ويتأكّد أن التقرير لم يتغيّر.

### محرّك التسعير

`services/pricing.py` وحدة **صافية** لا تلمس قاعدة البيانات ولا الواجهة —
وهي الموضع الوحيد الذي يُحسب فيه المال. قواعدها:

1. عدد الأيام = الفرق بين التاريخين، بحدّ أدنى يوم.
2. كل أسبوع كامل بالسعر الأسبوعي، والباقي باليومي.
3. **سقف الإنصاف**: الأيام المتبقّية لا تُكلّف أكثر من أسبوع كامل.
4. الخصم لا يتجاوز قيمة الإيجار، والإجمالي لا يكون سالباً.

### الاحتساب بالساعة

عند الإرجاع المبكّر تُحتسب المدّة بالساعات عبر `base_amount_hours()`:

```
الساعات   = فرق الوقت مقرَّباً لأعلى، بحدّ أدنى ساعة
أيام كاملة = الساعات ÷ 24   |   متبقٍّ = الباقي
الإجمالي   = base_amount(أيام كاملة) + min(المتبقّي × سعر الساعة، سعر اليوم)
```

الشقّ الأخير **سقف الإنصاف بالساعة**، نظير سقف الأسبوع: ساعات الكسر لا تُكلّف
أكثر من يوم كامل. والأيام الكاملة تمرّ على قاعدة الأسبوع كالمعتاد، فيجتمع
السقفان في حساب واحد.

يُحفظ في العقد `billing_mode` و `hours_count` و `hourly_rate_snapshot`، فتبقى
طريقة الاحتساب موثّقة في السجلّ وفي العقد المطبوع.

## ٥. التزامن والمعاملات

- **اتصال لكل خيط** (`threading.local`): كائن اتصال SQLite غير آمن للمشاركة،
  وخيط النسخ الاحتياطي يعمل بالتوازي مع الواجهة.
- **وضع WAL**: قراءة متزامنة أثناء الكتابة، فيقلّ خطأ «قاعدة البيانات مقفلة».
- **`BEGIN IMMEDIATE`** في كل عملية كتابة مركّبة: حجز فوري يمنع التعارض في
  منتصف العملية.
- **`PRAGMA foreign_keys = ON`** في كل اتصال — SQLite يعطّلها افتراضياً،
  وبدونها تصير قيود العلاقات زينة.

فتح العقد مثال كامل: إدراج العقد + تحديث حالة السيارة + تسجيل العربون + سجلّ
التدقيق، كلّها في معاملة واحدة. الحالة الوسطى — عقد مسجَّل وسيارة ما زالت
«متاحة» — كارثة تشغيلية لأنّها تسمح بتأجير السيارة مرّتين.

## ٦. الأمان

| الطبقة | الإجراء |
|---|---|
| كلمات المرور | PBKDF2-HMAC-SHA256، ٤٨٠٬٠٠٠ دورة، ملح ١٦ بايت لكل مستخدم |
| المقارنة | `hmac.compare_digest` لتفادي هجمات توقيت المقارنة |
| ترقية البصمات | تجديد تلقائي عند رفع عدد الدورات في إصدار لاحق |
| محاولات الدخول | قفل ١٠ دقائق بعد ٥ محاولات فاشلة |
| رسائل الخطأ | موحّدة عند خطأ الاسم أو كلمة المرور فلا تكشف الأسماء الموجودة |
| الصلاحيات | `@requires_role` في طبقة الخدمة، لا إخفاء أزرار فقط |
| SQL | معاملات مرتبطة (`?`) دائماً؛ أسماء الأعمدة من ثوابت داخلية لا من مدخلات |
| Google | نطاق `drive.file` فقط، والرمز المميّز بأذونات `0600` |
| حماية المدير | يستحيل تعطيل آخر حساب مدير |

## ٧. النسخ الاحتياطي

```
sqlite3.backup()  →  فحص السلامة  →  ضغط gzip  →  رفع  →  حذف الزائد  →  سجلّ
```

**لماذا `sqlite3.backup()` لا نسخ الملف؟** نسخ ملف SQLite أثناء عمل التطبيق
قد يلتقطه في منتصف عملية كتابة فتخرج نسخة تالفة، كما أن وضع WAL يبقي جزءاً من
البيانات في ملف `-wal` منفصل. الواجهة الرسمية تُنتج نسخة متّسقة والتطبيق يعمل.

**الاستعادة** تُنزّل ← **تفحص السلامة قبل المساس بأي شيء** ← تحفظ نسخة أمان
باسم `.pre-restore-…` ← تستبدل. النسخة التالفة تُرفض ولا تُمسّ البيانات الحالية.

**الخيوط**: الرفع يعمل في `QThread` منفصل فلا تتجمّد الواجهة، ولكل خيط اتصاله
الخاص بقاعدة البيانات.

## ٨. الواجهة العربية

- `app.setLayoutDirection(RightToLeft)` **مرّة واحدة** على مستوى التطبيق:
  تنعكس تلقائياً محاذاة النصوص وترتيب أزرار الحوارات ورؤوس الجداول وأسهم
  القوائم واتجاه شريط التمرير.
- **الخطوط**: سلسلة بدائل تبدأ بخطوط ويندوز الأصلية (Segoe UI ثم Tahoma)،
  فلا تُضمَّن ملفات خطوط في المستودع.
- **التواريخ**: مشكلتان حقيقيتان عُولجتا صراحةً:
  1. Qt **يعكس أقسام صيغة التاريخ** في الواجهات RTL، فيصير `yyyy-MM-dd`
     معروضاً `dd-MM-yyyy`. الحل: ضبط اتجاه حقل التاريخ LTR **قبل** ضبط الصيغة.
  2. `2026-09-01` داخل فقرة عربية ينقلب بصرياً إلى `01-09-2026` لأن الشرطة
     محرف محايد. الحل: `fix_dates()` تحيط كل تاريخ بعلامة LRM — في الجداول
     والتسميات وعقد PDF.
- **الجداول**: عرض كل عمود يُضبط على محتواه صراحةً بعد كل تعبئة. جُرِّب وضع
  `Stretch` التلقائي فكان يضغط عمود الاسم تحت عرضه فيظهر «محم…».
- **تصدير CSV** بترميز `utf-8-sig`: بدون علامة BOM يفترض Excel على ويندوز
  ترميز النظام فتظهر العربية حروفاً مبعثرة.

## ١٠. الترقية المستقبلية

`PRAGMA user_version` يقود ترقية المخطط في `core/migrations.py`.
لإضافة عمود في إصدار قادم: أضف خطوة جديدة إلى `MIGRATIONS` — **ولا تعدّل خطوة
قديمة بعد إطلاقها أبداً**، فقواعد البيانات في الميدان طبّقتها فعلاً.

**الإصدار 2** (الحجز المسبق والاحتساب بالساعة) يُسقط الفهرس القديم ويضيف أعمدة
الوقت وسعر الساعة. ولأن الترقية قد تُسقط عرضاً يعتمد على أعمدة تغيّرت، يعيد
`db.initialize()` تشغيل المخطط بعد أي ترقية فعلية — وكل عباراته `IF NOT EXISTS`
فلا أثر جانبي لإعادة تشغيله. يغطّي ذلك `tests/test_migrations.py` على قاعدة
بيانات مبنيّة بمخطط الإصدار الأول ومملوءة ببيانات.
